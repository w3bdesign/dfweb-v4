Solution:

  • Stories drop the hand-rolled mock wrapper
  • Locality: send-failure handling in one module

Shrink the CSRF surface

Speculative in-process

src/lib/csrf.ts · src/app/api/csrf-token/route.ts · src/app/api/form/route.ts · src/app/kontakt/page.tsx

Before · token reaches the form three ways

kontakt/page.tsx generates server-side → prop
GET /api/csrf-token exists — no caller found
/api/form accepts _csrf or csrfToken — two names, one seam
fallback secret "default-csrf-secret-…" silently used if env missing

After · one path, one name

csrf module

issueToken() · assertValid(token)

one field name · throws on missing secret in prod

kontakt page
/api/form

GET /api/csrf-token deleted (deletion test: passes)

Problem:
Three entry points and two token field names for one flow; the standalone token route has no caller.
Solution:
Delete the unused route, settle on one field name, fail loudly on missing secret.
  • Interface shrinks: two functions, one field name
  • Delete one route module
  • Silent insecure fallback becomes a loud failure

Top recommendation

Deepen the content module

Highest leverage: every route in the app crosses this seam, the error-mapping asymmetry is a live bug class, and the test suite already strains against it — mocking sanityFetch and unstable_cache separately in every test file. One interface, five call sites, one place to test.
